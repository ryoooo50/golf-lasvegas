# ラウンド共有 設計

2026-10-19

## 背景と目的

アプリを使っていたユーザー（以下「オーナー」）の友人が、自分でもアプリを使い始めようとしたときに「これまで一緒に回ったラウンドの記録を自分の方でも見たい」と言われたが、方法がなかった。

ラウンドごとに「この人に見せる」と共有でき、共有されたラウンドだけが友人のアプリにも表示されるようにする。自動同期ではなく、オーナーが選んだラウンドだけを見せる。

## ゴール

- オーナーがラウンド詳細から共有リンクを作り、LINE などで友人に送れる。
- 友人がリンクを開いてログインすると、そのラウンドが友人の履歴の「共有されたラウンド」に追加され、以後はリンクなしでアプリ内から見られる。
- 友人は見るだけ（編集不可）。オーナーが後でスコアを直すと友人側の表示も変わる（コピーではなく同じラウンドを見る）。
- オーナーはいつでも共有をやめられ、やめると友人側からも見えなくなる。

## 非ゴール

- ラウンドの共同編集・リアルタイム同期（友人がスコアを入力する）。
- 今後のラウンドを自動で友人に共有する仕組み。
- 友達登録・ユーザー検索・メールアドレスでの招待。
- ログインせずにリンクだけで見られる公開ページ。
- アプリ内通知（「共有されました」の通知など）。

## アンチゴール（動いても失敗とみなすもの）

- 共有された側が、オーナーのラウンドを変更・削除できてしまう。
- 共有をやめた後も、友人側に（端末キャッシュ以外で）見え続ける。
- 共有されたラウンドが友人自身のラウンドと混ざり、「再開」「複製」「削除」などオーナー向けの操作が出る。

## ユーザーと決めたこと

- 相手の指定は「LINE で送れる共有リンク」方式（メールアドレス指定や友達登録はしない）。
- リンクを開くにはログインが必要。開いたラウンドは友人の履歴に残る。
- 友人は閲覧のみ。オーナーの修正は友人側にも反映される。
- オーナーはいつでも共有を停止できる。
- リンクは転送されれば他の人も開ける（複数人が使えるリンク）。スコアなので許容する。

## 体験の流れ

### オーナー

1. 履歴 → ラウンド詳細を開く。
2. 「共有リンクを作る」を押す → リンクができ、「LINE などで送る」（端末の共有シート）と「コピー」ができる。
3. 共有中は、ラウンド詳細に「共有中（N人が追加済み）」と「共有をやめる」が出る。
4. 「共有をやめる」を押すと確認のうえ停止。リンクは無効になり、追加済みの人からも見えなくなる。もう一度「共有リンクを作る」と新しいリンクになる（古いリンクは使えないまま）。

### 友人

1. LINE でリンク（`https://golf-lasvegas.vercel.app/share?token=<token>`）をタップ。
2. ログインしていなければログイン画面を出す（「共有されたラウンドを見るにはログインしてください」）。
3. ログイン済みになったらサーバーに受け取りを登録し、そのラウンドの詳細（閲覧専用）を表示する。
4. 以後はアプリの履歴画面の「共有されたラウンド」から開ける。

注意: iPhone でホーム画面に追加した PWA と、LINE 内ブラウザ・Safari はログイン状態（保存領域）が別。友人が LINE 内ブラウザで受け取っても、受け取りはサーバーに記録されるため、後で PWA 側でログインしていれば一覧に出る。この前提を崩さないこと（受け取り状態を端末だけに持たない）。

## 仕様

### 共有リンク

- 1ラウンドにつき有効なリンクは最大1本。作成済みなら同じリンクを返す。
- トークンは推測できないランダム値（128bit 以上、URL セーフ）。
- 共有できるのは、ログイン中のオーナーがクラウドに保存済みのラウンドだけ（`cloudId` があるもの）。中断中（paused）のラウンドも共有できる（友人にはその時点までが見える）。
- ゲスト、または未同期のラウンドでは「共有リンクを作る」を出さず、理由（「ログインしてクラウドに保存されたラウンドだけ共有できます」）を短く表示する。

### 受け取り

- ログイン中のユーザーが有効なトークンで受け取ると、そのラウンドの閲覧メンバーになる（何度受け取っても1回分）。
- オーナー自身が自分のリンクを開いた場合は、メンバー登録せずにそのラウンド詳細を開く。
- 無効なトークン（存在しない・停止済み）は「このリンクは無効です（共有が停止された可能性があります）」と表示する。

### 閲覧

- 共有されたラウンドは読み取り専用。表示はラウンド詳細と同じ内容（最終結果・ニアピン・最小送金表）で、画像共有・CSV・PDF 出力は使える。「再開」「複製」「削除」は出さない。
- 友人は「一覧から外す」ができる（自分のメンバー登録だけを消す。オーナーの共有には影響しない）。

### 停止・削除

- 共有停止 = リンク削除 + 全メンバー削除。
- オーナーがラウンドを削除したら、リンクとメンバーも消える（DB の cascade）。
- 友人の端末に保存済みの共有ラウンドは、次に一覧を取得したときに消す。

## データモデル（neon/schema.sql に追記）

```sql
-- ラウンドの共有リンク（1ラウンド最大1本）
create table if not exists round_shares (
  round_id uuid primary key references rounds (id) on delete cascade,
  token text not null unique,
  created_at timestamptz default now() not null
);

-- 共有リンクから受け取ったユーザー
create table if not exists round_share_members (
  round_id uuid not null references rounds (id) on delete cascade,
  user_id text not null references "user" ("id") on delete cascade,
  created_at timestamptz default now() not null,
  primary key (round_id, user_id)
);
create index if not exists round_share_members_user_id_idx on round_share_members (user_id);
```

## API（Vercel Functions。認証は既存の `getSessionUserId`）

オーナー向け（`api/round-shares.ts` → `/api/round-shares`）。どれも `rounds.user_id` が自分のラウンドでなければ 404。

| メソッド | 内容 | 返り値 |
|---|---|---|
| `GET ?roundId=` | 共有状態 | `{ token: string \| null, memberCount: number }` |
| `POST ?roundId=` | リンク作成（既存なら同じものを返す） | `{ token, memberCount }` |
| `DELETE ?roundId=` | 共有停止（リンクと全メンバーを削除） | 204 |

友人向け（`api/shared-rounds.ts` → `/api/shared-rounds`）。

| メソッド | 内容 | 返り値 |
|---|---|---|
| `POST` body `{ token }` | 受け取り。オーナー本人ならメンバー登録しない | `{ roundId, isOwner }`。無効なら 404 |
| `GET` | 自分に共有されているラウンド一覧（`rounds` の行。現在有効なリンクがあるものだけ） | `{ rounds: SavedRound[] }` |
| `DELETE ?id=` | 自分を一覧から外す | 204 |

閲覧権限の判定は「`round_share_members` に自分がいて、かつ `round_shares` にそのラウンドの行がある」こと。停止時にメンバーも消すので通常は前者だけで足りるが、念のため両方見る。

## クライアント

- **ルート**: `/share`（`?token=` で受け取る）を追加。既存の `/round-detail?id=` と同じクエリ形式にして、静的書き出しで動的ルートを使わない。このルートは単体で開かれる（直リンク）ため、`authStore.initialize()` を自分でも呼ぶこと（今は `app/(tabs)/index.tsx` だけが呼んでいる）。未ログイン・ゲストなら `AuthScreen` を出し、ログイン後に受け取りを続行する。
- **ストア**: 共有されたラウンドは自分の `savedRounds` と分けて `sharedRounds` として持つ（端末に保存して、オフラインでも前回取得分を見られるようにする）。取得は、ログイン時（今 `loadCloudRounds` を呼んでいる箇所）と履歴画面を開いたとき。`SavedRound` → `RoundResult` の変換は `loadCloudRounds` の既存ロジックを共通化して使う。
- **履歴画面**: 自分のラウンド一覧の下に「共有されたラウンド」セクション（無ければ出さない）。各行は「詳細」と「一覧から外す」だけ。
- **ラウンド詳細**: `id` で自分のラウンドに無ければ `sharedRounds` から探す。共有ラウンドなら「共有されたラウンド」と表示し、オーナー向けの共有パネルは出さない。自分のラウンドなら共有パネル（作る／送る・コピー／共有中 N人／やめる）を出す。
- **リンクの URL**: `getApiBaseUrl()`（Web はページのオリジン、ネイティブは `EXPO_PUBLIC_API_URL`）に `/share?token=<token>` を付ける。
- **送る**: Web は `navigator.share`（使えなければコピー）、ネイティブは React Native の `Share`。コピーボタンは Web（`navigator.clipboard` がある場合）だけ。新しい依存は足さない。
- **文言**: ja / en の両方に追加。

## エッジケース

- 共有停止後に友人がリンクを開く → 無効表示。
- 共有停止後、友人の端末にキャッシュが残っている → 次回一覧取得で消える。取得までの間は見えてよい。
- オーナーがラウンドを削除 → 友人側も次回取得で消える。
- 友人がそのラウンドのプレイヤー名と同じ名前でも、紐付けはしない（表示だけ）。
- 3人モード・ニアピンありのラウンドも、そのまま同じ表示。

## テスト

- `server/api.test.ts`（ローカル Postgres、`npm run test:api`）に追加:
  - 他人のラウンドにはリンクを作れない・状態を見られない・停止できない（404）。
  - 受け取り → 一覧に出る。2回受け取っても1件。オーナー本人は `isOwner: true` でメンバーにならない。
  - 停止 → 無効トークンは 404、友人の一覧から消える。再作成で別トークン。
  - ラウンド削除で共有も消える。
  - 友人の「一覧から外す」でオーナー側の memberCount が減る。
  - 共有された側は `PATCH/DELETE /api/rounds` で変更できない（既存の所有者チェックのまま 404）。
- Jest: 変換関数の共通化、ストアの `sharedRounds` の取得・置き換え。
- ブラウザ: 本番ビルドを配信して、2アカウントで「作る → 別アカウントで開く → 一覧に出る → 停止 → 消える」を確認。開発サーバー（`expo start --web`）は既存の `import.meta` 問題で動かないので、`npm run build:web` の `dist/` を配信して確認する。

## 制約

- DB マイグレーション（`npx tsx --env-file=.env scripts/db-migrate.mts`）は main へのプッシュより先に本番へ適用する。
- Vercel Hobby プランの関数数上限（12）に注意。追加は2本で、現状 2本（auth, rounds）なので余裕あり。
- サーバーは ESM（`api/package.json`・`server/package.json` に `"type": "module"`）、import は `.js` 拡張子付き。
